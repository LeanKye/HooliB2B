# HooliB2B — сайт-визитка

**Живая версия: https://leankye.github.io/HooliB2B/**

Одностраничный сайт (SPA) для B2B-сервиса разработки и сопровождения digital-продуктов.
Анимации, живой фон, реагирующий на мышь, «liquid glass»-навигация, тёмная и светлая темы.

## Стек и почему именно он

| Технология | Зачем |
|---|---|
| **Next.js 16 (App Router) + `output: "export"`** | Полностью статическая сборка: сайт раздаётся как обычные HTML/CSS/JS, сервер не нужен, загрузка мгновенная. При этом есть SPA-переходы между разделами без перезагрузки. |
| **Tailwind CSS v4** | Быстрая вёрстка, mobile-first, тёмная тема через класс `.dark`. |
| **`motion` (Framer Motion)** | Появление блоков, «перетекающие» заголовки. Уважает `prefers-reduced-motion`. |
| **Нативный скролл** | Без сторонних библиотек: скролл ведёт композитор, а не main thread — иначе на ProMotion (120 Гц) страница просаживается до 60. |
| **Свой `<canvas>`-фон** | Частицы + аврора-пятна, реагирующие на курсор. Без тяжёлого WebGL. На телефонах рисуется в 1x и замирает во время скролла. |
| **Системные шрифты** | Ноль сетевых запросов за шрифтами → мгновенный первый рендер и никакого «прыжка» текста. |

Итого: ~1.3 МБ на всю сборку, никаких внешних сервисов и шрифтов, бэкенд не требуется.

## Команды

```bash
npm install        # установить зависимости
npm run dev        # дев-сервер → http://localhost:3000
npm run build      # статическая сборка в папку out/
npm run build:pages # сборка для GitHub Pages (с basePath /HooliB2B)
npm start          # локальный просмотр собранного сайта (npx serve out)
```

## Структура

```
app/
  layout.tsx              # <html>, тема, провайдеры, фон, навигация
  page.tsx                # главная: сборка всех секций
  globals.css             # токены тем, liquid glass, анимации
  icon.svg                # favicon (логотип)
  not-found.tsx           # 404
  partners/[slug]/page.tsx# страница кейса партнёра (генерируется статически)
components/
  background/AuroraBackground.tsx  # живой фон (canvas + параллакс от мыши)
  providers/ThemeProvider.tsx      # тёмная/светлая тема + localStorage
  providers/SmoothScroll.tsx       # MotionConfig + scrollToId()
  sections/                        # Hero, Services, Templates, Pricing, Process, Partners, Contact
  ui/                              # Logo, SideNav, ThemeToggle, Reveal, Section, ServiceIcon, TemplatePreview
lib/content.ts                     # ВЕСЬ контент сайта (цены, услуги, шаблоны, партнёры)
public/.nojekyll                   # чтобы GitHub Pages не пропускал папку _next через Jekyll
.github/workflows/deploy-pages.yml # авто-деплой на GitHub Pages
```

## Как менять контент

Почти всё правится в одном файле — `lib/content.ts`:

- `services` — продукты, цены внедрения, список возможностей;
- `templates` — каталог шаблонов (превью рисуется в CSS, см. `TemplatePreview.tsx`);
- `plans` — тарифы подписки;
- `process` — шаги работы;
- `partners` — клиенты для раздела «Наши партнёры»;
- `metrics` — цифры в первом экране;
- `navItems` — пункты боковой навигации (id должны совпадать с `id` секций).

### Как добавить партнёра

1. Добавьте объект в массив `partners` в `lib/content.ts` (обязательно уникальный `slug`).
2. Пересоберите сайт (`npm run build`). Страница `/partners/<slug>/` создастся автоматически —
   за это отвечает `generateStaticParams` в `app/partners/[slug]/page.tsx`.
3. Карточка появится в разделе «Наши партнёры», а внутри кейса — метрики, отзыв
   и кнопка перехода на сайт клиента (`url`).

## Деплой

Папка `out/` после `npm run build` — это готовый статический сайт.
Её можно залить на любой хостинг статики: Netlify, Vercel, Cloudflare Pages, GitHub Pages,
nginx, S3 — что угодно. Переменные окружения и бэкенд не нужны.

### GitHub Pages

Сайт живёт по адресу **https://leankye.github.io/HooliB2B/** и обновляется автоматически
при каждом пуше в `main` — за это отвечает `.github/workflows/deploy-pages.yml`.

Тонкость: Pages раздаёт проект из подкаталога `/HooliB2B/`, поэтому сборка делается
с `basePath` (см. `next.config.ts`). Он прокидывается переменной `NEXT_PUBLIC_BASE_PATH`,
так что локальная разработка остаётся в корне и ничего не ломается — один и тот же код
работает и на `localhost:3000`, и в подкаталоге на Pages.

Pages уже включён (Source: GitHub Actions), так что деплой идёт сам при каждом пуше
в `main` — никаких ручных шагов не нужно.

Если однажды будете поднимать Pages в новом репозитории: workflow пытается включить их
сам (`configure-pages` с `enablement: true`), но дефолтному `GITHUB_TOKEN` не хватает прав
на *создание* Pages-сайта (`Resource not accessible by integration`), поэтому нужен один
ручной клик — **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Собрать и проверить версию для Pages локально (без GitHub):

```bash
npm run build:pages
mkdir -p /tmp/pagesroot && ln -sfn "$PWD/out" /tmp/pagesroot/HooliB2B
cd /tmp/pagesroot && python3 -m http.server 4321
# → http://localhost:4321/HooliB2B/
```

> Если позже подключите свой домен, `configure-pages` вернёт пустой `base_path`
> и сайт соберётся для корня автоматически — править код не придётся.

## Мобильная версия

- **Навигация (две части), место контенту не занимает.**
  1. Плашка «где я» слева сверху. Название раздела **перекатывается барабаном**,
     как счётчик таймера в iOS: шаг считается по прокрутке (раздел меняется,
     когда чтение уже перешло к следующему — на середине подхода), а сам барабан
     доворачивается пружинкой за 460 мс, поэтому смена читается глазом, а не
     выглядит подменой слова. Края окна растворяет маска `mask-image` — соседнее
     название показывается и растаивает. Ширину окна задаёт невидимый дублёр со
     всеми названиями сразу: она равна самому длинному из них, поэтому на слове
     «Партнёры» плашка не «дышит». Нажатие открывает список всех разделов.
  2. Нижний лист (bottom sheet) со всеми разделами и отметкой «сейчас» —
     удобно дотянуться большим пальцем.
  Столбика точек слева больше нет: он занимал край экрана и дублировал то, что
  и так видно в плашке. Вместе с ним ушёл и левый отступ секций в 48 px, который
  держался под его ширину, — теперь контент начинается с 20 px (32 px на
  планшете) и занимает всю ширину экрана. Плашка и кнопка темы стоят на той же
  линии, что и колонка текста (по 20/32 px), и одной высоты — читается как
  осознанный ряд управления.
- **Вращающееся слово в первом экране.** Раньше оно было `inline-block` и при каждой
  смене размонтировалось: ширина схлопывалась, абзац переверстывался, и страница
  прыгала на ~28 px. Теперь все слова лежат в одной ячейке `inline-grid`, ширина
  слота равна самому длинному слову и не меняется никогда, а слово живёт в
  капсуле прямо внутри предложения — зарезервированное место читается как
  осознанный элемент, а не как «дыра» посреди строки.
- **Край экрана.** Раньше на iPhone сверху и снизу читались тёмные полосы, в
  которые «уезжали» элементы. Убрано тремя вещами: `viewport-fit=cover` (страница
  занимает экран целиком, включая вырез камеры и домашний индикатор),
  `theme-color` в тон верхней части авроры вместо почти чёрного `#04060c`, и
  фон на самом `<html>` плюс слой авроры, выступающий на 8 % за вьюпорт — любой
  «зазор» у края остаётся закрашенным. Дополнительно `overscroll-behavior: none`
  отключает «резиновую» оттяжку, из-за которой эти зазоры и появлялись.
- **Безопасные зоны.** Все фиксированные элементы (плашка, кнопка темы, нижний
  лист, подвал) отступают на `env(safe-area-inset-*)`, а перевод к разделу
  отсчитывает отступ от нижнего края плашки — заголовок не окажется под вырезом.

> Важно: полосы, которые рисует **сам браузер** (панель URL и кнопок в
> встроенном браузере Telegram, тулбар Safari), сайту не подчиняются. Код
> делает всё возможное со своей стороны — `viewport-fit=cover` и `theme-color`
> в тон фона, поэтому панели сливаются со страницей, а не читаются как чёрные
> полосы. Полностью убрать их можно только открыв сайт как отдельную вкладку
> или как Telegram Mini App, где хром не рисуется.

## Матовое стекло: почему в Chrome его не было

Тонкость сборки, из-за которой «liquid glass» работал только в Safari. В CSS
`backdrop-filter` писали парой:

```css
backdrop-filter: blur(16px) saturate(180%);
-webkit-backdrop-filter: blur(16px) saturate(180%);
```

Минификатор CSS (Lightning CSS внутри Next) считает прификсованную декларацию
той же логической property, что и обычную, и оставляет **последнюю** из пары. В
сборке оставалось только `-webkit-backdrop-filter` — а Chrome его не понимает
(`CSS.supports("-webkit-backdrop-filter", "blur(1px)")` → `false`), поэтому на
~25 «стёклах» вместо размытия оставался только полупрозрачный градиент. Safari
прификсованную форму понимает, поэтому проверка в WebKit ничего не показывала.

Лечится порядком: прификсованная форма идёт **первой**, обычная — второй:

```css
-webkit-backdrop-filter: blur(16px) saturate(180%);
backdrop-filter: blur(16px) saturate(180%);
```

Так в сборке остаются обе. Проверяется не глазами, а дисперсией пикселей: под
контрастной «шахматкой» за плашкой с работающим blur дисперсия падает со 117 до 27.

## Производительность на телефонах

Телефон грелся, а прокрутка дёргалась. Причины были конкретные, и каждая убрана:

| Что было | Что сделано |
|---|---|
| Четыре круга с `filter: blur(110–130px)` в бесконечной анимации — GPU размывал слой 700+ px заново на каждом шаге | Мягкость даёт многоступенчатый `radial-gradient` (`.aurora-blob`): тот же вид, почти нулевая цена |
| `backdrop-filter` на ~25 «стёклах» поверх анимированного canvas → пересборка кадра 60 раз в секунду | Матовое стекло осталось только на навигации и «пилюлях» (они зафиксированы или малы); крупные карточки вместо blur получили многослойный глянец — визуально стекло, по цене почти ноль |
| Матовое стекло в Chrome не применялось вовсе — сборка теряла декларацию (см. раздел выше), хотя в `getComputedStyle` в Safari всё выглядело рабочим | Порядок деклараций починен; на тач-устройствах blur остаётся ровно там, где задуман — на фиксированной навигации и мелких «пилюлях», крупные карточки по-прежнему без него |
| Canvas рисовался в 2x: на iPhone это 1.3 млн пикселей на кадр | На тач-устройствах 1x (вчетверо меньше пикселей), 30 кадров вместо 60 и меньше частиц |
| `document.documentElement.style.setProperty("--mx")` каждый кадр → пересчёт стилей всего документа | Переменные пишутся только при реальном изменении и только на устройствах с курсором |
| `mix-blend-overlay` во весь экран | На тач-устройствах режим наложения отключается |
| `filter: blur()` в анимации появления блоков и в смене слова | На тач-устройствах убрано: blur перерисовывает текст каждый кадр |
| Анимированный градиент в заголовках (`.text-gradient` → repaint текста каждый кадр) | На тач-устройствах градиент остаётся, но становится статичным |
| `will-change` у ~27 блоков появления навсегда → 27 слоёв композитора | Класс `.reveal` снимается после анимации (`Reveal.tsx`), слои освобождаются |
| Lenis перехватывал колесо и двигал `scrollTop` из `requestAnimationFrame` — скролл шёл на main thread и на ProMotion просаживался до 60 Гц | Lenis удалён, скролл нативный (композитор), переходы к секциям через `scrollIntoView({ behavior: "smooth" })` |
| Canvas перерисовывался во время прокрутки | Во время скролла отрисовка замирает (частицы ползут ~13 px/с — незаметно) и возобновляется через 140 мс |
| Бесконечная анимация «дыхания» авроры меняла фон под стеклянными элементами каждый кадр → `backdrop-filter` пересчитывался непрерывно | Пока идёт прокрутка, анимация пятен ставится на паузу (`html.is-scrolling`): фон под стеклом замирает, размывать заново нечего |

Замер до/после на главной (Playwright, 390×844): раньше при смене слова высота
страницы менялась 11604 ↔ 11577 px, а кнопка «Обсудить проект» уезжала на 28 px;
сейчас за 9 секунд (3 смены слова) верстка не сдвинулась ни на пиксель.

## Доступность

- `prefers-reduced-motion` уважается: анимации motion отключаются, canvas рисует
  один статичный кадр, прокрутка к разделам становится мгновенной, а барабан в
  плашке переставляется без движения (проверено: длительность перехода 1e-06s).
- `prefers-color-scheme` учитывается при первом заходе, дальше выбор хранится в `localStorage`
  (без «вспышки» белым — тема ставится inline-скриптом до первой отрисовки).
- Мобильное меню закрывается по `Escape`, кнопки отдают `aria-expanded` и `aria-current`.
- Canvas-фон паузится в неактивной вкладке.
